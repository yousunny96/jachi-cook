# 번역 수정 안내 (일본어 · 한국어)

화면은 **일본어가 기본**이고, 오른쪽 위 `日本語 | 한국어` 버튼으로 바꿉니다. 고른 언어는 브라우저에 기억됩니다.
일본어 문장은 모두 AI가 처음 번역한 것이라, 사람이 아래 파일을 열어 언제든 고치면 됩니다. 코드는 건드리지 않아도 됩니다.

## 어디를 고치나요

| 파일 | 들어 있는 것 |
|---|---|
| `dist/i18n/ja-ui.js` | 버튼·제목·안내·알림 등 **화면 문장** 약 250개. 화면별로 묶여 있습니다. |
| `dist/i18n/ja-catalog.js` | **재료·양념·도구 이름**, 냉장고 분류, 난이도, 요리 종류, **친구 8명의 이름·성격·대사** |
| `dist/i18n/ja-recipes.js` | **요리 60개**의 이름, 재료별 분량, 조리 순서, 한마디 팁, 물 |

한국어 원문은 원래 자리(`dist/app.js`, `dist/data.js`, `dist/data-japanese.js`, `dist/recipe-drafts.js`)에 그대로 있습니다.

## 고치는 법

```js
// dist/i18n/ja-ui.js
"내 냉장고": "わたしの冷蔵庫",        // ← 오른쪽 일본어만 고친다
"재료 {n}개 저장하기": "材料{n}個を保存", // ← {n}은 숫자가 들어갈 자리. 지우지 말고, 위치는 옮겨도 된다
```

- **왼쪽(한국어 원문, id)은 바꾸지 않습니다.** 앱이 이 글자로 번역을 찾습니다. 바꾸면 그 문장은 한국어로 나옵니다.
- `{n}` `{a}` `{b}` `{name}` `{list}` `{from}`: 숫자나 이름이 들어갈 자리라 그대로 둡니다.
- 친구 대사의 `{요리}` `{시간}` `{난이도}`: 요리 이름·분·난이도가 들어갈 자리라 그대로 둡니다.
- `<br>`는 줄바꿈, `<em>`은 강조라 그대로 둡니다.
- 재료는 `['화면 이름', ['검색용 다른 이름', ...]]` 모양입니다. 다른 이름을 추가하면 냉장고 검색과 "여러 재료 한꺼번에 담기"에서 그 말로도 찾습니다.
- 요리의 `steps`(조리 순서)는 개수를 늘리거나 줄여도 됩니다. `amounts`는 재료 id별로 하나씩 있어야 합니다.
- 일본어를 비워 두거나 지우면 그 자리는 한국어 원문이 보입니다.

## 고친 뒤 확인

```
node --test tests/*.test.cjs
```

`tests/i18n.test.cjs`가 아래를 알려 줍니다.
- 일본어 번역이 빠진 화면 문장, 재료, 요리
- `{n}` 같은 자리 표시를 실수로 지운 문장
- 일본어 화면 어딘가에 한국어가 남아 있는지(모든 화면과 요리 60개 상세를 그려서 확인)

## 반영

파일을 고쳐서 커밋하고 올리면 Vercel이 새로 배포합니다. 서버나 데이터베이스는 바꿀 필요가 없습니다.

## 새 문장이나 새 요리를 추가할 때(개발자용)

- 화면 문장은 코드에서 `t('한국어 문장')`처럼 쓰고, 같은 원문을 `ja-ui.js`에 추가합니다. 숫자·이름이 들어가면 `t('재료 {n}개', {n: 3})`처럼 씁니다.
- 새 재료·요리·친구는 한국어 데이터에 추가한 뒤 `ja-catalog.js`, `ja-recipes.js`에 같은 id로 일본어를 추가합니다.
- 테스트가 빠진 것을 잡아 주므로, 추가한 뒤 테스트를 돌리면 됩니다.

## 참고

- 언어 전환 처리: `dist/i18n.js` (고른 언어 기억, 문장 찾기, 데이터 이름 바꿔 끼우기)
- 일본어 화면에서도 한국어 재료 이름(예: 계란)으로 검색할 수 있습니다.
- 블로그 검색 링크는 한국어일 때 네이버 블로그, 일본어일 때 쿡패드(cookpad.com/jp)로 연결합니다.
- 서버 AI 기능(재료 인식, 조리 단계 생성)은 아직 한국어 기준입니다. 재료 인식은 일본어 단어도 받도록 안내문을 바꿨지만, 조리 단계 생성 결과는 한국어로 나옵니다(현재 화면에서는 쓰지 않음).
